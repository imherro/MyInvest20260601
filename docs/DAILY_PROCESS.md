# 每日流程标准

本文定义本项目日常运行顺序。目标是避免每天重做全部研究，也避免盘中临时改写主线、临时新增标的或临场生成未经验证的操作逻辑。

核心原则：

- 日常流程不是每天重做所有研究。
- 盘前以读取和执行检查为主，只有必要时才更新市场仓位。
- 盘中只检查已定义触发条件，不发明新策略。
- 盘后做复盘和必要更新。
- 周末或单独会话负责深度研究、补 ETF/个股档案和规则修订。

## 1. 文件读取顺序

每个日常任务开始前，至少读取：

1. `README.md`
2. `docs/PROJECT_MEMORY.md`
3. `docs/WORKFLOW.md`
4. `docs/RUNBOOK.md`
5. `docs/DAILY_PROCESS.md`
6. `docs/DATA_SOURCES.md`
7. `docs/FILE_NAMING.md`
8. `research/logs/decision_log.md`

然后按任务读取最新时间戳版本：

- 市场仓位报告：`research/market/market_score_YYYY-MM-DD_HHMMSS.*`
- 主线研究报告：`research/themes/theme_review_YYYY-MM-DD_HHMMSS.*`
- 主线登记册：`research/themes/theme_registry.json`
- ETF 登记册和 ETF 档案：`research/etfs/`
- 个股登记册和个股档案：`research/stocks/`
- 组合快照：`research/portfolio/portfolio_snapshot_YYYY-MM-DD_HHMMSS.*`
- 操作建议：`research/actions/action_plan_YYYY-MM-DD_HHMMSS_*.*`

注意：如果存在多个同类文件，默认读取时间戳最新版本。若不用最新版本，必须说明原因。

## 2. 盘前流程

目标：确认当天能不能操作、按什么边界操作、哪些条件触发才操作。

默认不重做所有研究。盘前优先读取：

1. 最新市场仓位报告。
2. 最新主线研究和 `theme_registry.json`。
3. 最新组合快照。
4. 最新 ETF/个股档案。
5. 最新操作建议或上一交易日待执行计划。

盘前只在以下情况更新市场仓位：

- 上一份市场仓位报告已经过期或不是最近交易日。
- 指数、成交、市场广度、主线状态或政策环境发生明显变化。
- 操作建议模块需要新的仓位边界。

盘前只在以下情况更新主线研究：

- 主线触发升级、降级或失效条件。
- 市场仓位或操作建议需要判断主线是否从确认转为分歧/退潮。
- 周末主线研究后有重大盘前事件。

盘前禁止事项：

- 不临时新增未建档 ETF 或个股作为买入候选。
- 不因为单日涨跌改写主线评级。
- 不绕过组合快照直接给操作建议。
- 不使用金额生成建议；当前项目按比例分析。

盘前输出可以是：

```text
research/actions/action_plan_YYYY-MM-DD_HHMMSS_premarket.md
research/actions/action_plan_YYYY-MM-DD_HHMMSS_premarket.json
```

## 3. 盘中流程

目标：只检查触发条件。

盘中读取：

1. 当日盘前操作建议。
2. 操作建议中的触发条件。
3. ETF/个股档案中的买入、加仓、减仓、失效条件。
4. 市场仓位报告中的触发式仓位调整表。

盘中允许输出：

- 触发提醒。
- 未触发说明。
- 风险失效提醒。
- 需要人工确认的异常。

盘中禁止事项：

- 不重做主线研究。
- 不临时改变市场仓位区间。
- 不新增未建档标的。
- 不把盘中波动解释成长期结论。

盘中输出可以是：

```text
research/alerts/intraday_alert_YYYY-MM-DD_HHMMSS.md
research/alerts/intraday_alert_YYYY-MM-DD_HHMMSS.json
```

## 4. 盘后流程

目标：复盘判断是否正确、触发是否执行、风险是否变化。

盘后读取：

1. 当日盘前操作建议。
2. 当日盘中提醒。
3. 实际执行记录，如用户提供。
4. 收盘后的市场、主线、ETF、组合变化。

盘后需要判断：

- 市场仓位分数是否需要更新。
- 主线阶段是否需要复核。
- 操作建议是否触发、是否执行、是否失效。
- 组合结构是否偏离更大。
- 是否需要写入决策日志。

盘后禁止事项：

- 不用事后结果重写事前判断。
- 不把复盘写成新的买卖建议。
- 不删除旧判断；只能记录偏差和修正。

盘后输出可以是：

```text
research/reviews/post_market_review_YYYY-MM-DD_HHMMSS.md
research/reviews/post_market_review_YYYY-MM-DD_HHMMSS.json
```

## 5. 周末流程

目标：做深度研究和系统维护。

周末适合做：

- 完整主线研究。
- ETF/个股档案补研究。
- 组合结构复核。
- 研究 backlog 更新。
- 决策日志复盘。
- 模块规则修订。

周末不应直接替代盘前操作建议。周末输出的研究结果应先固化，再由盘前或操作建议模块引用。

## 6. 单独会话分工

建议分工：

| 会话 | 职责 |
| --- | --- |
| 策略与流程会话 | 维护规则、流程、模块边界和项目记忆 |
| 市场仓位会话 | 更新市场仓位分数和触发式仓位表 |
| 主线研究会话 | 更新战略评级、交易评级和主线阶段 |
| ETF/个股补研究会话 | 逐只生成档案，不给最终买卖建议 |
| 操作建议会话 | 读取所有前置研究，生成比例级操作建议 |
| 盘中提醒会话 | 只检查已定义触发条件 |

## 7. 日常状态判断

每次开始任务时先判断属于哪一类：

| 场景 | 应做事项 |
| --- | --- |
| 只是盘前执行 | 读取最新文件，生成执行检查和触发条件 |
| 市场明显变化 | 更新市场仓位模块 |
| 主线触发条件变化 | 更新主线研究模块 |
| 持仓变化 | 更新组合快照 |
| 标的缺少档案 | 进入补研究会话 |
| 已有操作建议待执行 | 盘中只检查触发条件 |
| 规则反复失效 | 回到策略与流程会话修正规则 |

## 8. 推荐开场提示词

### 盘前

```text
请按 docs/DAILY_PROCESS.md 执行盘前流程。
读取最新市场仓位、主线研究、组合快照、ETF/个股档案和最新操作建议。
只生成盘前执行检查和触发条件，不临时改写主线，不新增未建档标的。
只按比例分析，不使用金额。
```

### 盘中

```text
请按 docs/DAILY_PROCESS.md 执行盘中流程。
只检查当日盘前操作建议、ETF/个股档案和市场仓位触发条件是否触发。
未定义的条件不要临时发挥；缺少档案时输出 blocked/research_first。
```

### 盘后

```text
请按 docs/DAILY_PROCESS.md 执行盘后流程。
对比盘前计划、盘中提醒和实际执行；不要用事后结果重写事前判断。
需要更新市场仓位、主线、组合或日志时，说明原因并生成时间戳文件。
```

### 周末

```text
请按 docs/DAILY_PROCESS.md 执行周末流程。
重点做主线复核、ETF/个股补研究、组合结构复核和决策日志复盘。
不要直接生成买卖建议；研究结果先固化，再供操作建议模块引用。
```
