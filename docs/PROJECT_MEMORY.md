# 项目记忆

本文是本项目的长期记忆文件。每台电脑继续工作前都应先阅读本文。每次形成新的策略决议、流程规则、重要反思或错误教训，都应更新本文并提交。

## 1. 项目目标

本项目用于辅助 A 股为主的投资决策。投资风格是长短结合，需要从研究分析到操作建议都有可审查逻辑。

目标不是让 AI 直接给出不可追溯的买卖建议，而是建立一套可复盘的投资决策系统：

- 市场环境判断
- 主线研究
- ETF/个股单独研究
- 组合仓位分析
- 操作建议
- 盘中提醒
- 盘后复盘
- 决策日志

## 2. 总体判断

不要把“全市场分析、主线判断、个股估值、ETF 分析、仓位建议、操作建议”塞进一条指令里。这样容易得到一篇看似完整、实际不可审计的投资作文。

正确做法是：

1. 每个模块单独研究。
2. 研究成果保存下来。
3. 后续操作建议必须读取并引用已有研究成果。
4. 当结论变化时，记录上调、下调、维持、移出或新增，以及变化原因。

## 4. 市场仓位分数

使用“市场仓位分数”，而不是“市场热度分数”。目的不是描述市场热不热，而是决定股票/ETF 权益仓位。

市场机会分数：

```text
 指数趋势20
+ 市场广度15
+ 成交量与流动性10
+ 资金流与风险偏好15
+ 主线强度15
+ 估值赔率15
+ 宏观政策环境10
```

市场仓位分数：

```text
市场仓位分数 = 市场机会分数 - 拥挤惩罚0~20
```

### 仓位映射

| 市场仓位分数 | 市场状态 | 权益仓位 |
| ---: | --- | ---: |
| 0-30 | 极弱/熊市 | 20%-30% |
| 31-45 | 弱势震荡 | 30%-45% |
| 46-60 | 中性修复 | 45%-60% |
| 61-75 | 强势可进攻 | 60%-75% |
| 76-85 | 高景气进攻期 | 70%-80% |
| 86-100 | 强趋势且风险未失控 | 75%-85% |

### 拥挤惩罚

拥挤惩罚用于从市场机会分数中扣分，避免追在高潮区。

拥挤惩罚包括：

- 指数连续大涨
- 成交额异常放大
- 龙头加速
- 主线成交占比过高
- 融资快速上升
- 散户情绪过热
- 高位放量滞涨
- 指数创新高但市场广度下降
- 主线内部开始掉队
- 估值分位过高

操作限制：

| 拥挤惩罚 | 操作含义 |
| ---: | --- |
| 0-5 | 正常配置 |
| 6-10 | 可以持有，谨慎追涨 |
| 11-15 | 不提高总权益仓位，只做结构调整 |
| 16-20 | 不新增进攻仓，考虑减仓或切防御 |

注意：拥挤惩罚已经从分数中扣除，不应再机械重复降仓。高拥挤时更适合限制新增进攻行为。

## 5. 硬约束

- 普通账户权益仓位上限：85%。
- 没有明确牛市主升浪证据：权益仓位不超过 75%。
- 没有 A 级主线：权益仓位不超过 65%。
- 市场广度低于 45%：权益仓位不超过 60%。
- 指数趋势低于 10 分：权益仓位不超过 60%。
- 主线强度低于 8 分：进攻仓不超过股票仓的 25%。
- 拥挤惩罚高于 15：不新增进攻仓。
- 单一行业/主线不超过权益仓位的 30%-35%。
- 主题仓不超过权益仓位的 10%。
- 单一个股一般不超过总资产的 8%-12%，除非是极高确定性长期核心资产。
- 任何买入都必须有买入理由、失效条件、减仓条件。

## 6. 股票仓内部结构

股票/ETF 权益仓内部建议分为：

- 核心仓：40%-55%，主要是 300ETF、500ETF、A500ETF、少量 QQQ 等。
- 进攻仓：25%-45%，只投 1-2 条 A 级主线。
- 防御仓：10%-20%，黄金、红利低波、公用事业等。
- 主题仓：0%-10%，机器人、商业航天、无人驾驶等，仅试错。

市场弱时：

- 核心仓提高
- 进攻仓降低
- 主题仓归零
- 防御仓提高

市场强时：

- 核心仓略降
- 进攻仓提高
- 主题仓最多 10%
- 防御仓保留底线

## 7. 主线研究原则

主线研究必须单独进行，不能在操作建议里临时重写。

A 级主线通常需要满足：

- 有产业逻辑
- 有政策或景气支持
- 有机构资金参与
- 板块 ETF 趋势向上
- 龙头持续创新高或强于指数
- 板块内部有扩散，不只是少数强势股
- 至少持续 5-10 个交易日

主线评级：

- A 档：主仓方向，可作为进攻仓核心。
- B 档：副线方向，可低配或观察。
- C 档：主题仓，仅试错。
- D 档：观察或回避。

主线变化必须记录为：

- 维持
- 上调
- 下调
- 移出
- 新增

并写明原因和对仓位的影响。

## 8. 保存格式决议

采用 Markdown + JSON，后期再考虑 SQLite。

- Markdown：负责人类阅读，保存研究报告、逻辑、变更原因、操作建议。
- JSON：负责结构化读取，方便 Codex 后续引用和自动化处理。
- Excel：后续可用于汇总展示，不作为核心数据库。
- SQLite：后期做查询、统计、回测时再引入。

初步目录规划：

```text
research/
  market/
  themes/
  etfs/
  stocks/
  portfolio/
  actions/
  logs/
```

## 9. 操作建议原则

操作建议必须引用前置研究结论，不能凭空给建议。

示例：

```text
建议加仓芯片 ETF：
依据1：市场仓位分数从62升至70，权益仓位允许提高。
依据2：半导体主线维持A档。
依据3：芯片ETF趋势向上，估值未进入高拥挤区。
依据4：当前组合进攻仓低于目标配置。
失效条件：半导体主线降至B档，或ETF跌破关键趋势位。
```

## 10. 已识别风险和错误教训

### 不要把复杂任务压成一条指令

全市场、主线、ETF、个股、组合、操作建议混在一起，会导致结论漂移且难以审查。

### 不要让主线判断每天摇摆

例如芯片/半导体是否是时代主线相对明确，但电力设备、军工等是否是一线主线，容易受搜索范围、上下文和模型临场判断影响。主线研究应先固化，再作为后续工作的依据。

### 不要重复惩罚拥挤

如果拥挤惩罚已经从市场机会分数中扣除，就不要再机械降仓。高拥挤更适合限制新增进攻仓。
