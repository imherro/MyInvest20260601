# 盘后复盘模块

本模块用于记录当天市场表现、盘前判断、盘中提醒、实际操作、执行偏差和后续修正。它不负责用事后结果重写当天的事前逻辑。

## 1. 模块目标

回答七个问题：

1. 盘前判断是否被市场验证？
2. 盘中提醒是否触发，是否有价值？
3. 实际操作是否符合计划？
4. 如果没有执行，原因是什么？
5. 持仓表现和组合风险有什么变化？
6. 哪些研究文件需要更新？
7. 是否存在需要修正规则的重复问题？

复盘的目标不是证明自己对，而是识别偏差并改进系统。

## 2. 必须读取的前置资料

盘后复盘至少应读取：

- 当日市场仓位报告
- 当日操作建议
- 当日盘中提醒
- 实际操作记录
- 当前持仓快照
- 主线登记册
- ETF/个股档案
- 决策日志

如果缺少实际操作记录，应明确写“未提供执行信息”，不能假设已经执行。

## 3. 复盘类型

| 类型 | 含义 |
| --- | --- |
| daily_brief | 每日简版复盘 |
| full_daily | 每日完整复盘 |
| weekly | 周度复盘 |
| event_driven | 重大事件复盘 |
| rule_review | 规则复盘 |

## 4. 复盘维度

### 4.1 市场判断复盘

检查：

- 市场实际表现是否符合盘前市场仓位判断。
- 指数趋势、广度、成交、资金、主线是否与预期一致。
- 是否出现意外风险或新催化。

### 4.2 主线判断复盘

检查：

- A/B/C/D 档主线是否表现符合评级。
- 主线内部是否扩散或收缩。
- 龙头是否继续强于指数。
- 是否需要触发主线模块临时更新。

### 4.3 操作计划复盘

检查：

- 盘前建议是否明确。
- 条件是否触发。
- 触发后是否执行。
- 未执行是否有合理原因。
- 是否存在临场情绪化操作。

### 4.4 组合风险复盘

检查：

- 总权益仓位是否仍在目标区间。
- 核心仓、进攻仓、防御仓、主题仓是否偏离。
- 单一主线、行业、个股是否集中。
- 是否有持仓逻辑失效或缺少档案。

### 4.5 执行复盘

检查：

- 实际买卖是否符合计划。
- 价格、仓位和节奏是否合理。
- 是否出现追涨、杀跌、犹豫、过度交易。
- 是否需要优化触发条件。

## 5. 判断偏差类型

| 偏差类型 | 说明 |
| --- | --- |
| market_misread | 市场环境判断错误 |
| theme_misread | 主线判断错误 |
| valuation_misread | 估值或赔率判断错误 |
| execution_deviation | 执行偏离计划 |
| emotional_trade | 情绪化交易 |
| missed_trigger | 条件触发但未行动 |
| false_trigger | 条件设计不合理，误触发 |
| missing_research | 因研究缺失导致无法判断 |
| no_issue | 无明显问题 |

## 6. 规则修正原则

不要因为单日涨跌轻易修改规则。

可以考虑修正规则的情况：

- 同类偏差重复出现。
- 触发条件明显过宽或过窄。
- 某个模块经常缺少关键输入。
- 操作建议经常无法执行。
- 风险约束被反复突破。

规则修正必须写入：

- `docs/PROJECT_MEMORY.md`
- 相关模块说明书
- `research/logs/decision_log.md`

## 7. 输出口径

每次盘后复盘必须包含：

- 日期
- 复盘类型
- 市场判断复盘
- 主线判断复盘
- 操作计划复盘
- 盘中提醒复盘
- 实际执行复盘
- 组合风险变化
- 判断偏差
- 需要更新的研究文件
- 第二天观察重点
- 决策日志条目

## 8. 与其他模块的关系

- 市场仓位模块可根据复盘触发下一次更新。
- 主线研究模块可根据复盘触发临时更新。
- ETF/个股档案可根据复盘更新操作条件。
- 操作建议模块可根据复盘改进触发条件。
- 决策日志记录复盘结论和规则修正。

## 9. 使用提示词

日常使用时，可以对 Codex 说：

```text
请按 docs/modules/POST_MARKET_REVIEW.md 和 templates/post_market_review_template.md 做今日盘后复盘。
必须对比盘前计划、盘中提醒和实际执行。
不要用事后结果重写事前判断；如果缺少实际执行信息，请明确标注。
```
