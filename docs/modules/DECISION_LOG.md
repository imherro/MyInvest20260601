# 决策日志模块

本模块用于保存关键结论变化和操作理由，形成长期可追溯记录。它不负责重新分析市场、主线、ETF 或个股，只负责把已经形成的结论、变化和执行情况记录清楚。

## 1. 模块目标

回答六个问题：

1. 什么时候做了什么判断？
2. 判断依据是什么？
3. 相比上次结论发生了什么变化？
4. 这个变化对仓位或操作有什么影响？
5. 后续需要观察什么？
6. 复盘时如何验证这次判断是否有效？

决策日志是项目的审计轨道。重要结论不能只留在聊天记录里，必须进入日志。

## 2. 需要记录的事件

以下事件必须记录：

- 市场仓位分数明显变化。
- 建议权益仓位上调或下调。
- 主线评级发生变化。
- ETF 操作评级发生变化。
- 个股操作评级发生变化。
- 形成具体操作建议。
- 实际执行买入、加仓、减仓、卖出。
- 盘后复盘发现判断偏差。
- 修改投资规则或模块模板。

以下事件可以简要记录：

- 日常维持原判断。
- 小幅评分变化但不影响仓位。
- 观察池更新。

## 3. 日志原则

- 不覆盖旧记录。
- 不只记录结论，必须记录原因。
- 不只记录建议，必须记录失效条件。
- 不把事后解释伪装成事前判断。
- 如果结论来自某个模块，必须写出来源文件。
- 如果实际操作和建议不一致，必须记录差异和原因。

## 4. 变化类型

| 类型 | 含义 |
| --- | --- |
| maintain | 维持原判断 |
| upgrade | 上调判断或仓位 |
| downgrade | 下调判断或仓位 |
| new | 新增判断、标的或规则 |
| remove | 移出判断、标的或规则 |
| execute | 实际执行操作 |
| review | 复盘 |
| revise_rule | 修正规则 |

## 5. 决策类型

| 类型 | 说明 |
| --- | --- |
| market_position | 市场仓位决策 |
| theme_rating | 主线评级决策 |
| etf_rating | ETF 评级或操作条件 |
| stock_rating | 个股评级或操作条件 |
| portfolio_adjustment | 组合结构调整 |
| action_plan | 操作计划 |
| execution | 实际执行 |
| post_market_review | 盘后复盘 |
| workflow_rule | 工作流或规则变更 |

## 6. 单条日志必须包含

- 日期和时间段
- 决策类型
- 变化类型
- 标的或主题
- 原结论
- 新结论
- 主要依据
- 对仓位或操作的影响
- 失效条件
- 来源文件
- 复盘入口

如果是实际操作，还必须包含：

- 操作类型
- 操作数量或仓位变化
- 执行价格或区间
- 是否符合原计划
- 不符合原计划的原因

## 7. 复盘字段

每条重要决策都应留下复盘入口：

- 复盘日期
- 需要验证的假设
- 成功标准
- 失败标准
- 后续处理方式

示例：

```text
复盘入口：
- 复盘日期：2026-06-08
- 验证假设：半导体主线资金持续流入，ETF 继续强于沪深300
- 成功标准：板块 ETF 未跌破 20 日线，主线评级维持 A
- 失败标准：主线降为 B 或 ETF 跌破关键趋势位
- 后续处理：若失败，暂停新增进攻仓
```

## 8. 日志文件

人类可读日志：

```text
research/logs/decision_log.md
```

结构化模板：

```text
templates/decision_log_entry_template.json
```

未来如果日志变多，再考虑迁移到 SQLite。

## 9. 与其他模块的关系

- 市场仓位模块输出重要仓位变化后，应写入日志。
- 主线研究模块发生评级变化后，应写入日志。
- ETF/个股档案评级或条件变化后，应写入日志。
- 操作建议模块生成明确操作建议后，应写入日志。
- 盘后复盘模块应回填执行结果和判断偏差。

## 10. 使用提示词

日常使用时，可以对 Codex 说：

```text
请按 docs/modules/DECISION_LOG.md，把本次市场仓位、主线、ETF、个股或操作建议的关键变化写入 research/logs/decision_log.md。
必须包含原结论、新结论、依据、影响、失效条件和复盘入口。
不要覆盖旧日志。
```
